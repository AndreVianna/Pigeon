Install Pigeon 0.7.0-beta.2

Four steps: install the command, start the service, add the plugin, connect two agents.

You need Windows 11 (or a supported Windows 10 Enterprise or LTSC edition), macOS, or Linux, and at least one of the agent tools in step 3.

Before you start

  • Close your agent apps (Claude, Codex, Antigravity, OpenCode, Copilot). Reopen them after installing so they find the pigeon command.
  • Use a computer that only you use. Pigeon's local service does not check who is calling it.
  • Use new test conversations and made-up messages for this beta, not real work or secrets.
Step 1of 4

1. Install the pigeon command

Each file is about 12 MB and includes everything Pigeon needs.

Windows

Download for Windows (x64, .msi)
  1. Run the .msi. It installs for you only and needs no administrator rights.
  2. The installer is not signed yet. If Windows shows "Windows protected your PC", choose More info, then Run anyway.
  3. Pigeon is installed to %LOCALAPPDATA%\Programs\Pigeon\pigeon.exe and added to your PATH.

If you use Claude Code, also install Git for Windows. The Claude plugin's hook runs under Git Bash.

macOS

Download for Apple Silicon (.pkg) Download for Intel (.pkg)
  1. Pick the package for your processor. The wrong one refuses to install.
  2. The package is not signed or notarized, so macOS may block it. If you decide to proceed, open System Settings > Privacy & Security and choose Open Anyway. Control-click does not bypass this on current macOS.
  3. Installing needs an administrator password. Pigeon is installed to /usr/local/bin/pigeon.

The Intel package is built but has not been run on an Intel Mac by the release checks. If you try it, please report the result.

On openSUSE, zypper install replaces dnf install.

  • The .deb and .rpm install to /usr/bin/pigeon.
  • Pigeon needs the SQLite library (libsqlite3), which nearly every distribution includes.
  • Install zenity (GNOME and most desktops) or kdialog (KDE) so Pigeon can show its approval windows. Without them, approvals are answered in a terminal with pigeon requests.
  • The ARM64 and RPM packages are built but have not been run on their systems by the release checks. If you try one, please report the result.

Check your download (optional)

The release includes SHA256SUMS.txt. Compare your file's SHA-256 with its line there. A checksum detects a changed download; it is not a code signature.

Windows
Get-FileHash .\Pigeon-0.7.0-beta.2-win-x64.msi
macOS
shasum -a 256 Pigeon-0.7.0-beta.2-osx-arm64.pkg
Linux
sha256sum pigeon_0.7.0.beta.2_amd64.deb

Had Pigeon as a .NET tool before? Remove it first: pigeon stop, then dotnet tool uninstall --global Pigeon.Cli.

Step 2of 4

2. Start the service

Open a new terminal and run:

Command line
pigeon --version
0.7.0-beta.2
pigeon start
Pigeon service started.
pigeon status
Pigeon service: running, version 0.7.0-beta.2
Connected sessions: 0 (and 0 agent connections not in a topic)
Sessions with waiting messages: 0

The service runs in the background until you stop it or restart the computer. It does not start by itself after a restart; run pigeon start again.

Step 3of 4

3. Add the plugin to your agent tools

Install the plugin in each tool you want to connect, then reopen the tool. Install the plugin, not only an MCP server: the plugin also brings the hooks that wake the agent and the connect skill.

Claude and Codex install the plugin straight from GitHub. The Antigravity, OpenCode and Copilot plugins are installed from a copy of the repository, so get one first:

git clone https://github.com/AndreVianna/Pigeon.git
cd Pigeon

Claude Code / Claude Desktop

In Claude Code, run:

/plugin install pigeon --marketplace AndreVianna/Pigeon

In Claude Desktop, add AndreVianna/Pigeon as a marketplace in the plugin settings and install pigeon.

Codex / ChatGPT desktop app

codex plugin marketplace add AndreVianna/Pigeon

Or add the repository in the app's Marketplace tab. Then install pigeon and approve its hooks when asked. If you added Pigeon earlier as a plain MCP server, remove that server first.

Antigravity App

Needs the Antigravity App 2.28 or later. From your copy of the Pigeon repository, run:

agy plugin install ./integrations/antigravity-plugin

Install it globally; Antigravity runs a plugin's background helper only from the global plugin folder. Then turn on Pigeon wake in the Automations dashboard, which is what wakes an idle conversation, and allow the Pigeon tools. Antigravity asks once for each tool, so the first wake stops until you have allowed pigeon_receive, pigeon_send and pigeon_wake_complete.

OpenCode 2

From your copy of the Pigeon repository, copy the folder integrations/opencode-plugin/pigeon to ~/.config/opencode/plugins/pigeon for all projects, or to .opencode/plugins/pigeon in one project. Then restart OpenCode.

The plugin needs OpenCode's server running, which the CLI and Desktop start. OpenCode 1.x is not supported.

GitHub Copilot

For the Copilot app, Copilot CLI, and VS Code chats with Copilot as the Session Target. From your copy of the Pigeon repository, run:

copilot plugin install ./integrations/copilot-plugin

The plugin allows Pigeon's own tools without asking; every other tool still asks. VS Code's older Local chats are not woken.

Step 4of 4

4. Connect two agents

  1. In the first agent, connect to a topic. In Claude, type /pigeon:connect parser-review. In the other tools, ask: "Connect to Pigeon topic parser-review." The agent reports that it is waiting for a partner.
  2. Do the same in the second agent with the same topic name.
  3. Ask either agent to send something to the other, for example: "Ask Codex to review the parser changes."

From then on, each message wakes the other agent while its conversation is open. Run pigeon status to see which sessions are connected and what is waiting.

Check

Check Pigeon without an agent

These six commands use two stand-in sessions. If the receive command prints your message, the service and its message store work. This does not test your agent tools.

pigeon join beta-cli-check as beta-cli-a using codex
pigeon join beta-cli-check as beta-cli-b using claude-code
pigeon send from beta-cli-a to beta-cli-check "PIGEON_BETA_CLI_01"
pigeon receive for beta-cli-b from beta-cli-check
pigeon leave beta-cli-check as beta-cli-a
pigeon leave beta-cli-check as beta-cli-b

The receive command should print a line containing PIGEON_BETA_CLI_01.

Later

Update

Close your agent apps, then run:

pigeon update --allow-pre-release

It downloads the newest release's installer for your system, checks it against SHA256SUMS.txt, installs it the way you installed Pigeon, and restarts a running service. On macOS and Linux it asks for your password through sudo. The flag matters during the beta: without it, pigeon update looks only at stable versions and finds nothing newer.

Version 0.7.0-beta.1 has no update command. Install 0.7.0-beta.2 with its installer once. After updating, update the plugins in your agent tools as well; they are separate from the command.

Uninstall

  • Windows: Settings > Apps > Installed apps > Pigeon > Uninstall.
  • macOS: run pigeon stop, then sudo rm /usr/local/bin/pigeon and sudo pkgutil --forget io.github.andrevianna.pigeon.
  • Linux: run pigeon stop, then sudo apt remove pigeon or sudo dnf remove pigeon.

Messages and the machine's identity stay in Pigeon's data folder until you delete it: %LOCALAPPDATA%\Pigeon on Windows, ~/Library/Application Support/Pigeon on macOS, ~/.local/share/Pigeon on Linux.

Help

If something goes wrong

An agent app cannot find pigeon

Close the app completely and open it again so it reads the new PATH. Desktop apps started from the macOS Dock or a Linux launcher may see a different PATH from your shell. If it still fails, report which installer and which app.

The installer says Pigeon is in use

An agent app's Pigeon plugin keeps the program running. Close your agent apps and try again.

Nothing wakes after a restart

The service does not start with the computer. Run pigeon start, then check pigeon status.

The agent got the message only when asked

That is polling, not a wake. Check pigeon status for that session's notification line, and please report it: this is what the beta is trying to find.
